# Skills and CLAUDE.md

This site is built with [Claude Code](https://claude.com/claude-code) as a day-to-day collaborator, using two different mechanisms: three custom commands that run on demand, and one instructions file that Claude Code reads automatically at the start of every session. Both have been in use since early in the project. This page is the first write-up of either.

## Custom commands

Three commands live in `.claude/commands/` as Markdown files. Each filename becomes a slash command — `check.md` runs as `/check`, and so on. Claude Code reads the file's contents as instructions when the command runs.

### /check

Runs the same style, spelling, and link checks that CI runs, so issues
surface locally before a push instead of in a failed GitHub Actions run.

1. Run Vale against `website/docs`, `website/blog`, and `website/src/pages`.
2. Run codespell against those same paths, plus `website/static/llms.txt`
   and `README.md`.
3. Run Lychee against every Markdown and MDX file in the site, plus
   `llms.txt` and `README.md`.
4. Report which checks passed, which found issues, and which were skipped
   because the tool isn't installed.

```
vale --config=.vale/.vale.ini website/docs website/blog website/src/pages
codespell website/docs website/blog website/src/pages website/static/llms.txt README.md
lychee --config .lychee.toml 'website/docs/**/*.md' 'website/docs/**/*.mdx' 'website/blog/**/*.mdx' 'website/src/pages/**/*.mdx' 'website/static/llms.txt' 'README.md'
```

### /new-post

Scaffolds a new blog post with correct frontmatter, so every post starts
from the same shape instead of copy-pasted from whatever post came before.

1. Take the post title as an argument, or ask for one if none was given.
2. Generate a slug from the title (lowercase, hyphen-separated, no special
   characters).
3. Create `website/blog/YYYY-MM-DD-{slug}.mdx`, dated with today's date,
   with the frontmatter and a `{/* truncate */}` marker already in place.
4. Remind the reviewer to replace the placeholder content, check the tag
   list, and add any images to `website/static/img/blog/`.

### /start

Starts the local Docusaurus dev server, checking first so a second one
doesn't get started by accident.

1. Check whether a Docusaurus dev server is already running. If so, report
   its URL instead of starting a duplicate.
2. If not, start one in the background using Node 20 via `nvm`.
3. Wait for the server's own "Docusaurus website is running" success
   message before reporting it's ready.
4. Report the local URL: `http://localhost:3000/showcase-site/`.

## CLAUDE.md

[CLAUDE.md](https://github.com/oddlittlebird/showcase-site/blob/main/CLAUDE.md) is a different mechanism from the preceding three commands. It isn't invoked by name; Claude Code reads it automatically at the start of every session in this repo, without anyone typing anything. Where a command is a set of steps run on request, CLAUDE.md is standing context: instructions that apply to the whole session, every time.

Right now it encodes one rule, specific to this repo: [website/docs/pipeline.md](/showcase-site/docs/pipeline) makes factual claims about this site's own pipeline, including how many GitHub Actions workflows exist, how many custom Vale rules exist, and what each tool does. Those claims have to keep matching the repo, not just read plausibly. CLAUDE.md tells Claude Code to re-check and update pipeline.md in the same change whenever a workflow, Vale rule, or other pipeline component it describes gets added, removed, or renamed, and gives the exact commands to compare against:

```
ls .github/workflows/ | wc -l
ls .vale/styles/Diana/ | wc -l
```

This is the same rule that [the pipeline test](/showcase-site/doc-detective/pipeline-test)
checks by machine, on a schedule. CLAUDE.md is the manual half: a standing
instruction Claude Code follows *while making a change*, rather than a check
that runs *after* one lands.
