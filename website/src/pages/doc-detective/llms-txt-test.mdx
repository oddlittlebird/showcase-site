# llms.txt verification test

This page shows the live result of a Doc Detective test that verifies this
site's `/llms.txt` file is reachable and still describes the site it belongs to.

## Why this matters

[`llms.txt`](https://llmstxt.org/) is the emerging convention for giving AI
tools a structured, machine-readable map of a site's content. It works like
`robots.txt`, but for language models and AI-assisted search rather than
web crawlers. The file tells AI agents what the site covers, where the key
pages are, and who built it.

The problem: `llms.txt` is a static file. No human clicks it, no browser
renders it, and nothing in a normal deployment pipeline checks that it still
responds or still says what it's supposed to say. It can silently 404 after a
URL restructure, or go stale after a content update, and no one notices until
an AI agent starts returning bad information about the site.

This test catches that failure automatically. It makes an HTTP request to the
live `llms.txt` endpoint and asserts that the file returns a 200 status and
is structurally valid: an H1 title and at least one `##` section heading. A
third step runs a shell script that fetches the live file, counts its `##`
headings, and compares the count against a stored baseline. If the file
disappears, returns an error page, loses its structure, or gains or loses a
section, the test fails and the badge below turns red.

This is a test written for a non-human reader of your docs. It covers a newer
and less obvious testing surface than "does this page render."

## How the test works

The test is embedded directly in this page's source as Doc Detective steps and
runs the following:

1. Make a GET request to the live `llms.txt` endpoint and confirm it returns
   HTTP 200.
{/* step {"httpRequest": {"url": "https://oddlittlebird.github.io/showcase-site/llms.txt", "method": "GET", "responseCode": 200}} */}

2. Make a second request and confirm the response body contains at least one `##`
   section heading, which the [`llms.txt` spec](https://llmstxt.org/) requires.
{/* step {"httpRequest": {"url": "https://oddlittlebird.github.io/showcase-site/llms.txt", "method": "GET", "responseCode": 200, "responseText": "/## /"}} */}

3. Run a shell script that fetches the live `llms.txt`, counts its `##`
   headings, and compares the count against the baseline stored in
   `llms-txt-headings.json`. The baseline updates automatically whenever
   `llms.txt` changes, so the count is never hardcoded.
{/* step {"runShell": {"command": "bash scripts/check-llms-headings.sh", "exitCode": 0}} */}

If the file is removed, its URL changes, the response no longer conforms to
the `llms.txt` format, or a section is added or removed without the baseline
being updated, one of these steps fails and the test is marked as failed.

## Run the test manually

If you clone this repo, you can run the test locally against the live site.
No local server is needed, because this test hits the deployed URL directly.

```bash
npm install -g doc-detective
doc-detective --config doc-detective/config.json --input website/src/pages/doc-detective/llms-txt-test.mdx
```

### Run the test on GitHub Actions

The test runs automatically every day and on every push to main that touches
`llms.txt` or this page. To trigger it on demand:

1. Go to the **Actions** tab in the GitHub repository.
2. Select **llms.txt verification test**.
3. Click **Run workflow**.
