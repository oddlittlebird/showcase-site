# API reference screenshot test

This page shows a screenshot of the [API reference](/showcase-site/api), captured automatically by Doc Detective rather than pasted in by hand.

## Why this matters

The [pipeline test](/showcase-site/doc-detective/pipeline-test) checks static content: markdown that Docusaurus renders once, at build time. This page checks something more fragile — a live, third-party render pipeline. The [API reference](/showcase-site/api) isn't part of this site's build output. Every time someone loads it, [Scalar](https://scalar.com) fetches a script from a CDN, fetches the OpenAPI spec, and renders the whole reference client-side, in the browser, on the spot. Any of those steps can break independently of anything in this repo: the CDN can be unreachable, a Scalar release can change how it renders, the spec file can go missing.

That said, this test proves the pipeline produced *something*, not that the something is correct. A separate [comparison step](#how-the-test-works) narrows that gap by checking the rendered output against a reference image, not just its presence.

## How the test works

The test is defined directly in this page's source as embedded Doc Detective steps. It runs in a fixed 1280×800 Chrome viewport, so the screenshots keep the same dimensions as the reference image even when the CI runner's default browser window size changes. The test runs the following:

{/* test {"testId": "api-reference", "runOn": [{"browsers": [{"name": "chrome", "viewport": {"width": 1280, "height": 800}}]}]} */}

1. Navigate to the [API reference](/showcase-site/api).
{/* step {"goTo": "http://localhost:3000/showcase-site/api"} */}

2. Confirm Scalar mounted its rendered heading element, proving the client-side render pipeline actually produced output instead of an empty or broken page.
{/* step {"find": {"selector": "h1.section-header-label", "timeout": 20000}} */}

3. Capture a screenshot and save it as `api-reference.png`.
{/* step {"screenshot": {"path": "website/static/doc-detective/api-reference.png", "overwrite": "true"}} */}

4. Capture a second screenshot and compare it against the reference image saved at `api-reference-baseline.png`, allowing up to 2% pixel difference. A pixel difference greater than 2% reports WARNING, not FAIL — see [the screenshot comparison test](/showcase-site/doc-detective/screenshot-comparison-test) for what `maxVariation` actually does. Before it compares pixels, though, Doc Detective checks that the two images have matching aspect ratios, and a mismatch there does fail the step.
{/* step {"screenshot": {"path": "website/static/doc-detective/api-reference-baseline.png", "maxVariation": 0.02, "overwrite": "aboveVariation"}} */}

{/* test end */}

## What makes this test fail

The test fails in two cases:

- `find` can't locate an `h1.section-header-label` element within 20 seconds. In practice that means the CDN script never loaded, the OpenAPI spec never fetched, or Scalar's render broke badly enough to produce no heading at all.
- The aspect ratio of the new screenshot differs from that of the reference image by more than 5%. Doc Detective can't compute a pixel difference between images of different shapes, so it fails the comparison step instead of reporting a variation. Because the step fails before it can overwrite the reference image, the test keeps failing on every run until someone replaces that image. The fixed viewport exists to prevent this: in October 2026, the CI runner's default Chrome window got 57 pixels shorter, and every run failed this check until the test pinned its viewport.

It does *not* fail if the page renders with broken, wrong, or degraded content, as long as some element matching that selector exists. The [comparison step](#how-the-test-works) narrows this gap without turning it into a hard failure: because this page rarely changes, a WARNING here is a meaningful signal that something visual actually shifted, worth checking even though it doesn't redden [the badge](#latest-result).

## Run the test manually

If you clone this repo, then you can run the test locally.

```bash
npm install -g doc-detective
cd website && npm run build && npx docusaurus serve --no-open &
doc-detective --config doc-detective/config.json --input website/src/pages/doc-detective/api-reference-test.mdx
```

### Run the test on GitHub Actions

The test runs automatically every day and on every push to main that touches the API reference or this page. To trigger it on demand:

1. Go to the **Actions** tab in the GitHub repository.
2. Select **API reference screenshot test**.
3. Click **Run workflow**.
