This page shows two screenshots of the [homepage](/showcase-site/), captured automatically by Doc Detective at two different viewport sizes: a typical mobile width and a typical desktop width.

## Why this matters

The [pipeline test](/showcase-site/doc-detective/pipeline-test) and the [API reference test](/showcase-site/doc-detective/api-reference-test) both check a page at a single, fixed viewport. Neither one would notice if a layout change broke the mobile experience while leaving desktop untouched, or the other way around. Responsive bugs are exactly that kind of failure: the markup and the content are both fine, but the page falls apart at a width nobody happened to be looking at. This can happen when CSS changes without enough test coverage, or when some other update shifts the layout without anyone noticing.

This page defines two separate tests that each run the same two steps: navigate to the homepage, then take a screenshot. The only difference between them is the `runOn` viewport configuration. One requests a 375×812 viewport (a common mobile breakpoint). The other requests 1280×800 (a common desktop breakpoint).

Requested and rendered aren't always identical: some browser automation setups enforce a minimum window width regardless of the viewport a test asks for. Treat the two screenshots below as the ground truth for what actually rendered, not the numbers above.

## What makes this test fail

Each test only fails if the browser can't reach the homepage at all. Neither test compares the screenshot against a previous version, so a layout that renders but looks wrong, content overflowing its container, a broken breakpoint, an element overlapping another, will not turn the badge above red. This test proves the page still renders at both widths, not that it renders well. Catching a visual regression like that is the job of screenshot comparison (`maxVariation`), a separate, later test in this series.

## Run the test manually

If you clone this repo, then you can run the test locally.

```bash
npm install -g doc-detective
cd website && npm run build && npx docusaurus serve --no-open &
doc-detective --config doc-detective/config.json --input website/src/pages/doc-detective/responsive-test.mdx
```

### Run the test on GitHub Actions

The test runs automatically every day and on every push to main that touches this page. To trigger it on demand:

1. Go to the **Actions** tab in the GitHub repository.
2. Select **Responsive screenshot test**.
3. Click **Run workflow**.
